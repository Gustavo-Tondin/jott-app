# packaging/

Everything that turns the source into something installable, one folder per
platform, plus the two scripts that drive a release.

| Path | What |
|---|---|
| `release.sh` | The whole release in one command: bump, test, preflight, audit, commit, tag, push (asks first), optional APK, and copies what got built into `releases/`. `npm run release -- <version>`; `--collect` only refreshes `releases/`. It refuses to tag a version with no `## vX.Y.Z` section in `CHANGELOG.md` — that section is half of the release page. |
| `linux/` | `PKGBUILD` + `jott.desktop` (Arch: `cd packaging/linux && makepkg -si`). The AppImage, `.deb` and `.rpm` need nothing here — the Tauri bundler makes them. |
| `windows/` | `windows-preflight.sh`, the cross-compile check that runs before a tag. |
| `android/` | Notes on the APK. The Gradle project itself is generated by Tauri under `src-tauri/gen/android/` and stays there — the build system expects that path. |
| `releases/` | The latest built installers, side by side, under the names the release page uses — `jott-windows.exe`, `jott-ubuntu.deb`, `jott-fedora.rpm`, `jott-linux.AppImage`, `jott-arch.pkg.tar.zst`, `jott-android.apk`. The version is not in the name; `versions.tsv` beside them remembers it and the README tabulates it. Binaries are gitignored; only the README is versioned. |

Where the tools actually write: Tauri → `target/release/bundle/`; the Windows
cross-compile → `target/x86_64-pc-windows-msvc/`; Gradle →
`src-tauri/gen/android/app/build/outputs/`; makepkg → `linux/`. All of that
is build output and gets cleaned; `releases/` is the copy that survives.
